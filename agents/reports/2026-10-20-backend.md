## What was built, by step

**1. Baseline and fff.** Baseline refreshed in both modes (`../reference/baseline.md` rewritten). fff is published to
`.build/fff/lib/libfff_c.a`; `make x86_64` and `make fff-universal` build other architectures. Third-party
notices are generated (`scripts/gen-notices.py` → `THIRD_PARTY_NOTICES.md`).

**2. Persistent service.** New ops `pick` (picker first draw from `SuggestionIndex`) and `search` (index held open
in an `OpenIndex`, reopened when another process saves it). Search code moved into a new `SmcliSearch` library.
The search corpus is updated per record. The service is on by default, and a client restarts a service left by
an older build (`build` identity in every response). fff/context caches are LRU-bounded.

**3. Shell adapters.**
- Zsh: hook arrays, `$pipestatus` (schema v5), `HISTORY_IGNORE`.
- Bash: bash-preexec → PS0 → DEBUG trap, chains an existing EXIT trap, keeps `PROMPT_COMMAND` arrays, honors
  `HISTIGNORE`/`HISTCONTROL`.
- New Fish adapter (`shell-init fish`).
- Up/Ctrl-R stay bound by default (keys another tool already bound are left alone); the other extra keys need
  `SMCLI_EXTRA_KEYS=1`.
- `scripts/test-shells.py` rewritten around shell variants, with a prompt-counter sync.

**4. Directory context.** `DirectoryContext.swift` (Git discovery incl. worktrees, operation state, manifests read
declaratively) and `ContextCache.swift` (async `git status --porcelain=v2`, FSEvents invalidation, 5 s freshness,
LRU 16). `smcli context` and a `context` op.

**5. fff search.** `SmcliFFF` wrapper (linked only into `smcli-service`), pool of at most 4 instances with idle
eviction, `files`/`grep`/`select` ops, `file_selections` (schema v6). Ctrl-T in the picker cycles
history/files/grep. Per-shell quoting (`ShellQuoting.swift`); selections are inserted, never executed.

**6. Ranking.** Project boost, query → selection feedback (`command_selections`, schema v7), session transitions,
manifest scripts/targets as candidates, git-state hints, each listed in `why`. `SMCLI_RANKING_OFF=…` turns
signals off one at a time.

**7. Validation.** New tests: a shared service killed under four live shells, stale and corrupt search indexes,
writes from other processes, a 50k-file repo, cache eviction. x86_64 binaries pass the service and file-picker
tests under Rosetta.

## Issues found and fixed along the way

- Bash Ctrl-C hang in tests: the harness passed on an ignored SIGINT; the pty child now resets it.
- `PROMPT_COMMAND` assertion: the test was wrong for bash-preexec, not a race.
- fff didn't index files created before its watcher was ready (trees of 5k+ files): it now waits for the watcher.
- The git output reader on the shared GCD pool caused flaky `git init` under parallel tests: it now runs on its own thread.
- Ranking fixture bug (transition pairs had mismatched sessions), fixed before the baseline was recorded.

## Known limitations

- Writes from another process (fallback record, import, prune) make the next search cost ~760 ms (full rebuild);
  native history file changes and the 5-minute frecency refresh also rebuild the corpus.
- Warm grep at 50k files (~1.5 s) is over fff's 1 s budget, so results may be partial.
- Bash doesn't record pipestatus. In PS0/bash-preexec modes, an ignoredups duplicate under ignorespace/HISTIGNORE
  isn't recorded. Zsh `zshaddhistory` exclusions aren't consulted.
- Fish start times are whole seconds, and fish's native history file isn't read by picker or search.
- Transitions need `SMCLI_SESSION`, which shells only get after reloading `shell-init`.
- Swift script candidates are limited to `swift build --target X`; Package.swift parsing is regex-based (it lists
  `CSQLite`, a dependency name, as a target).
- `smcli-service` now embeds the Potion model (~34 MB), like the CLI.
- Schema v7: older smcli binaries refuse the database as "newer".
- One unexplained 963 s duration was recorded once under bash-preexec (it looks like a sandbox clock jump, not reproduced).
- Swift unit and shell tests were not run on x86_64; universal binaries were built but not run.
