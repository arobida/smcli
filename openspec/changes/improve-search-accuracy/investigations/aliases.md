# Alias investigation

## Decision: NO-GO

Do not ship automatic alias snapshots or enable group 7 for aliases on this evidence. Query-side expansion improves recall on a tiny synthetic cohort, but does not improve top-1, the grammar cannot guarantee secret-free payloads, and fish capture is expensive. This is an investigation result, not a production implementation. Revisit with an explicitly approved program/subcommand/flag vocabulary or user-approved aliases, a mutation-driven freshness mechanism, and a larger independent cohort.

## Scope and method

Read the proposal, design, tasks and both spec deltas. Only group 4 was implemented. Production hooks, protocol, database, embeddings and other worktrees were not changed.

Reproduce:

``` sh
python3 scripts/spike-aliases.py
make ranking
```

`scripts/spike-aliases.py` starts clean noninteractive bash/zsh/fish processes with synthetic definitions; it never sources user rc files or reads native history. Bash reads `alias -p` without eval, zsh reads its live `aliases` map, and fish inspects `abbr --show` and the literal single-command forwarding bodies generated by `alias`. Arbitrary fish functions are not expanded. Serialization quotes are removed only as delimiters; interior quotes are rejected. No alias body is executed.

The shell filter accepts ASCII word expansions separated by single spaces: letters/digits/underscore/hyphen, with a letter-led first word. Names are capped at 32 characters, bodies at 128; bash/zsh inspect at most 128 definitions, fish at most 128 abbreviations plus 128 functions. Thus fish's upper record budget is twice the others; these limits are prototype safeguards, not a finished wire format. Discovery/serialization itself can still scan the shell's full table, and truncation can hide an alias. Unknown/omitted aliases must be neutral.

Tests accept `gst=git status`, `gl=git log`, and fish `agst` abbreviation. They reject `deploy=TOKEN=abc123 ./deploy.sh` from the spec, substitutions, backticks, operators, redirection and quoted strings. Bash 3.2 received an additional direct capture/secret-example check. Timings use bash 5.3.20, zsh 5.9 and fish 4.9.3 on Darwin arm64.

The isolated test in `crates/smcli-search/tests/ranking.rs` uses the existing real Potion/TalaDB engine and deterministic synthetic World. It queries the original form and an additional first-word-expanded form, retaining the suffix and interleaving/deduplicating their ranked results (original first). It neither compares independently normalized scores nor rewrites returned commands. No recursive expansion. A session-keyed in-memory map tests conflicting `gl` definitions, full-snapshot replacement/removal and isolation. Another fixture verifies literal recorded `gst` and recorded `git status` both survive the union. These are fixture-level lifecycle checks, not service transport tests.

## Ablation results

Same seven cases, same corpus/context, expansion supplied versus withheld. The switch is test-local; no production `SMCLI_RANKING_OFF=alias` was added (group 7 is gated).

| Query / state                       | Expected command        | Off rank | On rank |
| ----------------------------------- | ----------------------- | -------- | ------- |
| `gst`, status snapshot              | `git status`            | 2        | 2       |
| `gl`, log snapshot                  | `git log --oneline -20` | absent   | 2       |
| `gl --oneline`, log snapshot        | `git log --oneline -20` | 1        | 1       |
| `gl`, conflicting session: ls-files | `git ls-files`          | 7        | 2       |
| `gl`, snapshot removed              | `git log --oneline -20` | absent   | absent  |
| `gst`, no snapshot                  | `git status`            | 2        | 2       |
| `git status`, non-alias             | `git status`            | 1        | 1       |

Ranks are measured in the fixture's returned list; absent has reciprocal rank zero. Each form retrieves up to ten results; the union is not a shipped ten-result truncation policy.

| Metric (n=7) | Off          | On           | Delta                    |
| ------------ | ------------ | ------------ | ------------------------ |
| MRR          | 0.448980     | 0.571429     | +0.122449                |
| Top-1        | 2/7 (28.57%) | 2/7 (28.57%) | 0 percentage points      |
| Top-3        | 4/7 (57.14%) | 6/7 (85.71%) | +28.57 percentage points |

The four active-snapshot cases alone improve MRR from 0.410714 to 0.625000 (+0.214286), top-1 remains 1/4, and top-3 rises from 2/4 to 4/4. Do not mistake these hand-selected cases for held-out validation. Original-first interleaving explains why a good expansion cannot displace an unrelated original top hit. No fusion tuning was attempted.

`make ranking` passes both tests. The original 34-case test still reports search n=16 and suggest n=18, each MRR/top-1/top-3 1.000. Production ranking was not changed, so its baseline delta is zero; this does not establish safety of enabling expansion on that cohort. Notes/no-session guard cases also explicitly compare the absent-snapshot path against existing search.

## Hook latency and freshness

The following measures the proposed capture work, not an installed end-to-end hook or IPC. Fifteen independent shell batches each perform twenty captures redirected to `/dev/null`; divide batch wall time by twenty. Startup and definition setup remain amortized in the numbers. P50 is the median batch average; p95 is nearest-rank p95 (the maximum of fifteen batch averages), not the p95 of individual hook events. The Python script uses a monotonic wall clock.

| Shell | Added synthetic aliases | p50 ms/capture | p95 ms/capture |
| ----- | ----------------------- | -------------- | -------------- |
| bash  | 10                      | 2.161          | 2.257          |
| bash  | 100                     | 6.202          | 6.275          |
| zsh   | 10                      | 1.053          | 1.153          |
| zsh   | 100                     | 3.637          | 4.616          |
| fish  | 10                      | 21.743         | 22.231         |
| fish  | 100                     | 25.848         | 28.314         |

The synthetic safety aliases and shell defaults are additional to those counts. Fish measurements include abbreviation and function discovery; no optimized fish variable bridge was assumed. This is unacceptable as work repeated on every prompt. Capture-on-start plus capture-on-change could amortize it, but reliable change notification is not supplied by this prototype. Polling and comparing snapshots every prompt still pays discovery/filter cost even if transmission is suppressed. Wrapping `alias` alone misses `unalias`, zsh direct map mutation, fish function changes and abbreviation changes. No zero-cost freshness claim is made. No send/serialization/service/query-latency benchmark was run; expansion performs a second search and needs a separate end-to-end latency budget before approval.

## Privacy review

The specified assignment-bearing secret example is rejected before any candidate transmission in all three shells. Quotes, substitutions, path separators and operators also fail the allowlist. No eval, shell expansion or rc parsing is used. Test process output intentionally includes only synthetic data, including the privacy counterexample below.

**Blocking counterexample:** `alias baresecret='deploy abc123'` passes every shell's simple-word filter. A credential can be a bare word, a program-like name or a flag; syntax rejection cannot identify it. Even `git clone` plus a bare credential-like argument is not made safe merely by rejecting assignments. Limiting lengths does not solve this. Generic lexical validity is not a semantic program/subcommand/flag allowlist, so this filter must not ship as the privacy guarantee.

A future approved implementation must revalidate at the request boundary, replace complete per-session snapshots (including empty snapshots), expire state, avoid cross-session fallback, send only on start/change, and provide identical request-local CLI fallback behavior. It must never store snapshots in SQLite, command logs or document embeddings, and must redact alias bodies from `why`, diagnostics and protocol logging. The expanded query also needs review of pick/query persistence and diagnostics: merely keeping the snapshot in memory does not prevent an expanded secret from leaking through query recording. The spike bypasses production requests and records no new picks, so it does not prove these end-to-end properties.

## Checks and limits

Passed shell assertions in all three installed shells, additional macOS bash 3.2 check, and `make ranking` (two tests). Native history was never opened by the spike. No production build, `make fresh`, full `make test`, PTY interactive-hook suite, Linux run or protocol fixtures were needed or run. No claim is made for general fish functions, global/suffix aliases, alias recursion, complex quoting, stale transport or a held-out accuracy floor. Keep alias shipping tasks gated by this NO-GO.
